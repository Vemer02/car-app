# Ответы на декларации RuStore Консоли

Заполняется в форме загрузки версии. Консоль сама заранее отмечает типы данных по разрешениям из манифеста,
**проверьте список и дополните вручную**: данные, которые вводит сам пользователь или которые уходят на сервер без
системного разрешения, она не увидит.

## 1. «Категории и типы данных»
Отметьте все, что приложение собирает или передаёт (в том числе через SDK):

| Тип в форме | Что у нас |
|---|---|
| Имя | Имя или логин из профиля Яндекс/Telegram при входе через них |
| Адрес электронной почты | Вход по почте; почта из профиля Яндекс |
| ID пользователей | Идентификатор аккаунта, Telegram ID, Яндекс ID |
| Другие финансовые данные | Суммы расходов и стоимость обслуживания, которые вводит пользователь (не банковские данные). Консервативно лучше отметить |
| Фото (раздел «Фото и видео») | Фото чеков и документов, которые пользователь сам выбирает или снимает. Если такого пункта в форме нет — ближайший по смыслу |
| Другой пользовательский контент | Записи об обслуживании, комментарии, описания работ, названия напоминаний |
| Идентификаторы | Технический идентификатор устройства для push; рекламный идентификатор, который получает рекламный SDK |

Не собираем: местоположение, контакты, телефон, сообщения, календарь, историю просмотров, платёжные данные.
Рекламному модулю геолокация и персонализация запрещены в коде.
Если форма предлагает «Диагностика» / «Отчёты об ошибках»: свои отчёты о сбоях мы не ведём, но рекламный SDK
Яндекса может собирать диагностику — **сверьтесь с документацией Яндекса** и отметьте, если собирает.

Передача третьим лицам (в формах, где это спрашивают): Рекламная сеть Яндекса (технические данные устройства для
показа рекламы), RuStore (идентификатор для push), Telegram (текст уведомления — только если пользователь сам
включил дублирование в Telegram).

## 2. «Чувствительные разрешения» (поле «Обоснование»)
Из разрешений нашего приложения чувствительным по списку RuStore будет **`POST_NOTIFICATIONS`**.
Остальные (интернет, вибрация, отпечаток пальца, фоновые задачи push и т. п.) — обычные и декларации не требуют.
Камеру и доступ к файлам приложение **не запрашивает** — фото выбираются через системные окна.

Текст обоснования для `POST_NOTIFICATIONS`:
```
Приложение показывает уведомления о приближающихся сроках обслуживания автомобиля, об окончании ОСАГО и техосмотра и о напоминаниях, которые пользователь создал сам. Других уведомлений приложение не показывает.
```
После сборки откройте на странице запуска блок «Паспорт сборки» → «Разрешения»: там полный список. Если в нём
окажется что-то кроме перечисленного, скажите мне.

## 3. Рекламные решения (п. 9.4: заявить обязательно)
- Рекламная сеть / SDK: **Yandex Mobile Ads SDK** (Рекламная сеть Яндекса), версия 8.0.0.
- Формат: «Реклама при открытии» (App Open) — одно рекламное окно при запуске, не чаще раза в 15 минут,
  с кнопкой закрытия.
- Персонализация и геолокация: выключены.
- Данные из приложения (автомобили, записи, расходы, фото, почта) в рекламную сеть не передаются.
- Описано в политике конфиденциальности (п. 9.8).
- Прямых рекламодателей и других рекламных SDK нет. Если добавим — декларацию нужно будет обновить **до**
  выхода версии: незаявленные SDK — основание для снятия приложения (9.9).

## 4. Платёжные решения (п. 9.1)
Нет. Приложение бесплатное, встроенных покупок, подписок и сторонних платёжных систем нет.
Платное отключение рекламы пока не делали; когда появится — декларировать заранее.

## 5. Тип приложения (6.1)
Бесплатное. Платной функциональности нет.
