# Автолюбитель — Android-приложение

React Native + TypeScript + свой сервер (mygarazh-server) + WatermelonDB (offline-first).

## 1. Создать проект

Эти файлы — не полный RN-проект: нативные папки `android/`/`ios` генерирует CLI.
**Версию React Native нужно зафиксировать** — иначе CLI создаст нативную часть под самую
свежую версию RN, а `package.json` из архива рассчитан на 0.75.4, и сборка не сойдётся.

```bash
npx @react-native-community/cli@latest init CarApp --version 0.75.4
cd CarApp
```

(Старая команда `npx react-native init` в новых версиях удалена, а TypeScript теперь
включён в шаблон по умолчанию — отдельный шаблон не нужен.)

Затем скопируйте из архива поверх созданного проекта: папки `src/`, `legal/`, `scripts/`,
`.github/`, файлы `App.tsx`, `package.json`, `tsconfig.json`, `babel.config.js`,
`.gitignore`. Папки `legal/` и `scripts/` обязательны: `npm install` запускает
`scripts/build-legal.js` (генерирует `src/legal/generated.ts`, без которого приложение
не соберётся).

## 2. Зависимости

```bash
npm install
```

Все зависимости уже перечислены в `package.json`. **Закоммитьте появившийся
`package-lock.json`** — сборка в GitHub Actions (`npm ci`) без него не запустится.

Добавьте в `.gitignore`: `android/app/google-services.json`, `.env`, `.firebaserc` —
в них ключи и идентификаторы вашего проекта.

## 3. Свой сервер (mygarazh-server)

Приложение общается с бэкендом по обычному REST API — никакого Firebase. Адрес сервера
задан в `src/config.ts` (`API_BASE_URL`). По умолчанию там `https://api.mygarazh-app.ru` —
если сервер развёрнут на другом домене, поменяйте эту строку перед сборкой.

Сам сервер (регистрация, вход, гаражи, синхронизация, согласие, удаление аккаунта) —
отдельный проект `mygarazh-server`, разворачивается на VPS через Docker Compose. Как его
поставить и проверить — в README и `РАЗВЁРТЫВАНИЕ.md` того проекта, здесь не дублируем.

Перед первой сборкой убедитесь, что сервер отвечает:
```bash
curl https://api.mygarazh-app.ru/v1/health
```
Должно вернуть `{"status":"ok"}`.

## 3.5. Политика конфиденциальности и согласие на обработку данных

Тексты — в `legal/privacy-policy.md` и `legal/consent.md` (это **два отдельных документа**:
с 1 сентября 2025 года ст. 9 152-ФЗ прямо запрещает объединять согласие на обработку
персональных данных с политикой, пользовательским соглашением или чем-либо ещё). Из них
`node scripts/build-legal.js` (запускается автоматически при `npm install`) собирает:

- `src/legal/generated.ts` — тексты для экранов внутри приложения, доступны без интернета;
- `public/privacy.html`, `public/consent.html`, `public/delete-account.html` — те же тексты
  как публичные веб-страницы. Google Play требует ссылку на политику конфиденциальности и,
  для приложений с регистрацией, ссылку на страницу удаления аккаунта. **Эти три файла
  отдаёт сам сервер** `mygarazh-server` (по адресам `/privacy`, `/consent`,
  `/delete-account`) — после `npm run legal` скопируйте их в папку `public/` того
  репозитория и разверните заново, см. его `РАЗВЁРТЫВАНИЕ.md`, раздел «Публичные страницы
  политики».

**Перед первым запуском:**

1. Откройте `legal/operator.json` и заполните все поля (название/ИП, ИНН, адрес, email,
   `dataLocation` — где физически расположен ваш сервер, например «Россия, г. Москва»
   по адресу дата-центра, который подтвердил хостер). Пока поля не заполнены, в текстах
   стоят метки `[НЕ ЗАПОЛНЕНО: …]` — с ними публиковать приложение нельзя, но для
   локальной разработки это не блокирует сборку.
2. `npm run legal` — пересобрать после любой правки.

**Как это устроено в приложении:**

- Экран регистрации email/паролем — отдельная галочка (`ConsentCheckbox`), по умолчанию
  не отмечена. Без неё кнопка «Зарегистрироваться» подсвечивает ошибку и не пускает дальше.
  Согласие фиксируется сразу после успешной регистрации (`POST /v1/consent`).
- Если в будущем добавится вход без этой галочки (например, снова через соцсеть) — для
  таких случаев есть отдельный `ConsentScreen`, показывается после входа, если согласие
  ещё не зафиксировано.
- Согласие журналируется на сервере (`consent_log`, только дописывается, не редактируется
  и не удаляется — это ваше доказательство факта согласия на случай проверки).
- **До согласия ничего не уходит на сервер.** Синхронизация в `App.tsx` включается только
  при `consentState === 'accepted'`.
- **Удаление аккаунта** — `DELETE /v1/me` на сервере (`mygarazh-server/src/account.js`,
  тесты там же). Удаляет профиль, журнал согласий, свой гараж со всеми данными, заявки и
  приглашения, затем сам аккаунт входа. Из чужого гаража — просто исключает. Участников
  своего гаража возвращает в их собственные гаражи — общие данные они теряют.
- При существенной правке текстов увеличьте `version` в `legal/operator.json` — все
  пользователи, у кого согласие дано на более раннюю редакцию, снова увидят `ConsentScreen`.

    queries.ts        — реактивные выборки

## Как получить APK для тестировщиков

**Самый простой путь — облачная сборка без компьютера с Android Studio:** подробная
пошаговая инструкция «для чайников» — в файле `ТЕСТ-НА-ТЕЛЕФОНЕ.md`. Workflow
`.github/workflows/build-test-apk.yml` сам создаёт пустой проект React Native нужной версии,
кладёт в него файлы из репозитория, собирает APK и выкладывает его в Releases. Секретов
для сборки не нужно вообще: адрес сервера — это просто строка в `src/config.ts`, не тайна.

Почему собирается именно **release**, а не debug: debug-APK не содержит код приложения и на
любом телефоне без компьютера с Metro покажет красный экран «Unable to load script».
Release здесь подписан стандартным отладочным ключом React Native, поэтому ставится на
любой телефон. Для публикации в Google Play нужен свой ключ подписи — это отдельный этап.

**Локальная сборка** (если поставлены Android SDK и JDK 17, проект создан по разделу 1):

```bash
cd android
./gradlew assembleRelease
# APK: android/app/build/outputs/apk/release/app-release.apk
```

Требует установленных Android SDK и JDK 17 на машине, где собираете.

## Окно «Что нового»

Перед каждым новым релизом откройте `src/whatsnew/entries.ts` и добавьте новую запись
**в начало** массива `WHATS_NEW`: номер версии на 1 больше предыдущего, дата, заголовок
и несколько строк простым языком — что человек теперь может делать нового, без терминов.
Старые записи не удаляйте — если кто-то давно не обновлял приложение и пропустил сразу
несколько версий, он увидит все пропущенные разом при следующем запуске, а не только
последнюю. Окно хранит «уже видел» на самом устройстве, а не на сервере — если сменится
пользователь на том же телефоне, окно не всплывёт по новой с чужой историей.

## Реализовано

- **Напоминания об ОСАГО и техосмотре** (`screens/Dashboard/AddReminderScreen.tsx`) —
  кнопка «+» в разделе «Напоминания» на Dashboard. В отличие от напоминаний о замене
  жидкостей, которые пересчитываются сами при внесении записи ТО, эти заводятся и
  обновляются вручную — дата окончания полиса/карты не связана с логом обслуживания.
  Потребовала версии 2 локальной схемы (`src/db/schema.ts` + `src/db/migrations.ts`) —
  на существующих установках WatermelonDB применит миграцию сама, без потери данных.
- **Обслуживание учитывается в тратах** (`utils/spending.ts`). Раньше стоимость из записи ТО
  видна была только в «Сервисе»: в «Расходы» и в итоги на главном экране попадало лишь то, что
  внесено формой «Добавить расход». Теперь записи ТО со стоимостью подмешиваются к расходам при
  показе — в итог за месяц («в том числе обслуживание …»), в разбивку по категориям (строка
  «Обслуживание»), в список по дням (с описанием работ), в поиск и в график на главном экране.
  Данные намеренно НЕ дублируются в таблицу расходов: копия разъезжалась бы с оригиналом
  (удалили запись ТО — «расход» остался бы висеть), а так удаление/правка в «Сервисе» сразу
  отражается везде. Строка обслуживания в «Расходах» не удаляется оттуда (долгое нажатие
  подсказывает, где). CSV-экспорт расходов остаётся прежним (только расходы), ТО экспортируется
  отдельно.
- **Сторож «API, которых нет в React Native»** (`scripts/check-rn-apis.js`, запускается в
  облачной сборке первым шагом и останавливает её при находке): `URLSearchParams.get/set`,
  `new URL()`, `structuredClone` и т. п. в Node работают, а на телефоне бросают «not implemented»
  — так сломалась синхронизация (первая же ошибка, которую показала строка «Синхронизация»)
  и вход через Яндекс. Вместо `URLSearchParams` — `utils/query.ts`.
- **Видимый статус синхронизации** (Гараж → «Синхронизация»): зелёная точка и время последней
  успешной отправки, либо красным — причина («403 consent_required», «нет связи с сервером»
  и т. п.); нажатие запускает проверку немедленно. Раньше любая ошибка уходила только в
  `console.warn`, и поломка могла неделями оставаться незамеченной. Экран передачи машины и
  экран приёма тоже показывают настоящую причину ошибки вместо общей фразы про интернет.
- **Свайпы.** Между вкладками (влево — следующая, вправо — предыдущая; `components/withTabSwipe.tsx`)
  и на главном экране по блоку с пробегом — смена машины (`hooks/useSwipe.ts`). Без новых
  нативных библиотек: стандартные нижние вкладки React Navigation сами свайп не умеют, поэтому
  свайп сделан на штатном `PanResponder`. Жест «забирается» только когда он явно
  горизонтальный, вертикальная прокрутка и нажатия не страдают; вложенный блок с пробегом
  выигрывает у внешнего свайпа вкладок. Логика порогов — отдельно в `utils/swipe.ts`
  и проверена тестом, а вот сам жест на живом телефоне проверяется только руками.
  **Анимации:** экран идёт за пальцем (с «резинкой» у края, когда дальше листать некуда), при
  отпускании плавно уезжает, а следующий так же плавно въезжает с противоположной стороны —
  и при свайпе, и при нажатии на вкладку внизу. То же при смене машины свайпом по пробегу.
  Всё на штатном `Animated` с нативным драйвером (идёт мимо JS-потока), без новых библиотек.
  Параметры (доля смещения, длительности) — константы в начале `components/withTabSwipe.tsx`.
  **Белые вспышки при переходах** (нашлись по видео с телефона): во время анимации экран
  полупрозрачен, и сквозь него проступало всё, что лежит ПОД ним, а там было светлое — у
  навигации не было своей тёмной темы, у сцен вкладок и стеков не было фона, а фон окна
  Android по шаблону белый. Теперь тёмными сделаны все четыре слоя (`navTheme`,
  `sceneContainerStyle`, `contentStyle`, а фон окна `scripts/ci.js` прописывает в
  `styles.xml` из токенов темы). Экраны при анимации гаснут не до нуля (`MIN_OPACITY`).
- **Запись о ТО подробнее.** Поле «Что было сделано» (идёт первым, затем тип работ),
  стоимость разделена на «работы» и «запчасти» с живым «Итого» (`cost` остаётся итоговой
  суммой — всё, что считается по ней, не изменилось; у старых записей разбивки нет, и мы её
  не выдумываем). Поиск ищет и по описанию/суммам, плюс фильтр по типу работ чипами под
  строкой поиска (показываются только типы, которые есть в записях). В CSV-экспорт добавлены
  колонки. Потребовало версии 4 локальной схемы и миграции 011 на сервере.
- **Реальный расход топлива (л/100км)** (`src/utils/fuelEconomy.ts`, карточка «Средний
  расход» на экране «Расходы») — классический способ «от заправки до заправки». Для
  этого у расходов появилось необязательное поле «пробег на заправке» (показывается
  только для категории «Топливо», подставляется последний известный пробег машины) —
  без пробега на момент каждой заправки расстояние между ними неоткуда взять, а
  «сколько литров купили» само по себе расходом не является. Расчёт идёт по заправкам
  за всю историю, не только за текущий месяц; заправка без пробега считается «разрывом
  цепочки» и через неё не перепрыгивают — иначе расстояние за два цикла делилось бы на
  объём одного, давая правдоподобное, но неверное число. Потребовал версии 3 локальной
  схемы — миграция применится на уже установленных телефонах сама.
- **Передача машины новому владельцу по QR-коду** (долгое нажатие на машину в Гараже →
  «Передать новому владельцу», `screens/Garage/TransferCarScreen.tsx` +
  `AcceptTransferScreen.tsx`) — вся история ТО и расходов переезжает в гараж нового
  владельца, у прежнего мягко удаляется (тот же механизм, что при обычном удалении
  машины). QR-код — через `react-native-qrcode-svg`, чистый JS поверх уже имеющегося
  `react-native-svg`, без новой нативной линковки. Ссылка умеет открывать приложение
  напрямую, если оно уже установлено (своя простая схема `carapp://`, не полноценные
  Android App Links — для них нужна ещё проверка владения доменом, отложили). **Перед
  публикацией** впишите реальную ссылку на приложение в RuStore вместо
  `REPLACE_ME_package_id` в `mygarazh-server/public/transfer.html` (кнопка «Установить
  приложение» на странице, которую видит новый владелец, если приложение у него ещё не
  стоит).
- **Экспорт истории в CSV** (`src/utils/csvExport.ts`, кнопка со стрелкой в заголовке
  экранов «Обслуживание» и «Расходы») — через обычную системную «Поделиться», без новых
  зависимостей. Специально под Excel с русской локалью: разделитель колонок — точка с
  запятой, не запятая (она там десятичный разделитель), и метка кодировки в начале файла,
  иначе кириллица могла бы открыться нечитаемыми символами. Это первая часть пункта
  «PDF/CSV» из плана — PDF не делал осознанно: потребовал бы новую нативную библиотеку,
  которую я не смог бы проверить так же надёжно, как это удалось с CSV.
- **Поиск по истории** ТО и расходов (`src/utils/search.ts` — чистая логика сопоставления,
  без зависимости от React Native, легко проверяется тестом) — ищет по названию работы,
  заметке, категории/типу (по русскому названию, не по внутреннему коду), сумме и пробегу.
  Во время активного поиска список расширяется с текущего месяца на всю историю, а карточки
  «итого за месяц» на экране расходов на это время скрываются — иначе цифры были бы о месяце,
  а список под ними — обо всём времени сразу.
- **Дублирование уведомлений в Telegram-боте** (экран Гаража → «Уведомления в
  Telegram») — для тех, кому по какой-то причине не приходит push (нет RuStore,
  агрессивная экономия батареи на телефоне и т. п.). Включено по умолчанию у тех, кто
  вошёл через Telegram; остальные привязывают аккаунт прямо в настройках, тем же
  ботом, что и для входа. Можно выключить в любой момент, не теряя саму привязку.
- **Push-уведомления о ТО** через RuStore (`src/services/push.ts`) — сервер сам проверяет
  раз в 30 минут, кому пора напомнить, и шлёт всем участникам гаража. Требует настройки
  проекта в RuStore Консоль на сервере (см. `mygarazh-server/РАЗВЁРТЫВАНИЕ.md`, раздел
  «Push-уведомления») и `RUSTORE_PUSH_PROJECT_ID` в `src/config.ts`. **Единственная часть
  всего проекта, написанная по документации без личной проверки** — пакет SDK ставится
  с сервера, недоступного из моей рабочей среды; весь код, завязанный на него, нарочно
  собран в несколько строк одного файла (`src/services/push.ts`), чтобы было легко
  поправить при необходимости.
- **Окно «Что нового»** (`src/whatsnew/entries.ts` + `services/whatsNew.ts` +
  `components/WhatsNewModal.tsx`) — показывается один раз на устройство после обновления
  приложения, простым языком. См. раздел выше, как добавлять записи.
- **Сброс пароля по email** (`screens/Auth/ForgotPasswordScreen.tsx`) — ссылка приходит
  на почту, сама смена пароля проходит на веб-странице `/reset-password` на сервере, не
  в приложении. Требует настройки почтового ящика на сервере, см.
  `mygarazh-server/РАЗВЁРТЫВАНИЕ.md`, раздел «Сброс пароля по email».
- Auth: экраны логина/регистрации по email/паролю (`src/services/auth.ts`), сессия с
  автообновлением токена (`src/services/api.ts`).
- **Вход через Telegram-бота** (`src/services/telegramAuth.ts` + `hooks/useTelegramLogin.ts`)
  — требует настройки бота на сервере, см. `mygarazh-server/РАЗВЁРТЫВАНИЕ.md`, раздел
  «Вход через Telegram», и `TELEGRAM_BOT_USERNAME` в `src/config.ts`. В отличие от версии
  на Firebase — без Cloud Functions и без платного тарифа: и код, и секрет подтверждения
  генерирует сам сервер. Статус заявки на вход опрашивается раз в 2 секунды (обычный REST
  не умеет сам "толкать" обновления, в отличие от Firestore).
- **Вход через Яндекс ID** (`src/services/yandexAuth.ts` + `hooks/useYandexLogin.ts` +
  `components/YandexLoginModal.tsx`) — настоящий OAuth в окне внутри приложения
  (`react-native-webview`), без системного браузера и без диплинков. Настройка
  OAuth-приложения — на сервере, см. `mygarazh-server/РАЗВЁРТЫВАНИЕ.md`, раздел «Вход
  через Яндекс». На мобильное приложение ничего переносить не нужно — ClientID живёт
  только на сервере, телефону присылается уже готовая ссылка на вход.
- **Политика конфиденциальности и согласие на обработку ПД** (см. раздел 3.5) — отдельные
  документы согласно 152-ФЗ, галочка на регистрации, журнал согласий на сервере, удаление
  аккаунта из приложения и по публичной ссылке.
- Dashboard: пробег, ручное обновление, ближайшее ТО с прогресс-баром, напоминания, расходы за месяц.
- Гараж: список авто, добавление авто, переключение активного авто, базовые настройки.
- Обслуживание: список записей ТО по месяцам, добавление записи (авто-апдейт напоминания и пробега).
- Расходы: список за месяц, разбивка по категориям, добавление расхода (с учётом топлива).
- Удаление: долгое нажатие на авто/запись ТО/расход — с подтверждением; удаление авто каскадно
  удаляет его записи ТО, расходы и напоминания.
- **Синхронизация со своим сервером** (`src/db/sync.ts`, HTTP): офлайн-первая, тот же протокол
  WatermelonDB, что и раньше, только по REST вместо Firestore — сервер сразу отдаёт raw-записи
  в формате, который ждёт локальная база, поэтому никакого маппинга полей на клиенте не нужно.
  Локальная база «привязана» к гаражу: при вступлении в общий гараж, выходе из него (в т.ч. на
  другом своём устройстве) или входе другого аккаунта синхронизация сама дошлёт
  несинхронизированное и безопасно перезальёт базу. Работает в фоне (раз в 60 сек, пока
  пользователь авторизован — см. `App.tsx`), плюс сразу после любого локального изменения и по
  pull-to-refresh на Dashboard/Service/Expenses.

- **Биометрия** (`src/services/biometrics.ts`): замок поверх уже открытой сессии через
  `react-native-keychain` — при возврате в приложение из фона просит отпечаток/Face ID,
  прежде чем показать данные. Включается тумблером в Гараже, реализовано в `App.tsx` (`AppState`).

- **Совместные гаражи** (`src/services/garages.ts`): полноценная модель на несколько
  участников — код приглашения (6 символов, живёт 7 дней), заявка на вступление,
  одобрение любым текущим участником, автоматическое переключение активного гаража
  у вступившего. UI — секция «Участники гаража» на экране Гаража, с pull-to-refresh
  (в отличие от версии на Firestore, заявки теперь не обновляются сами вживую — сервер
  не push-уведомляет клиента, обновление только по запросу).

Все экраны работают полностью офлайн на WatermelonDB — изменения копятся локально и
досинхронизируются, как только появится сеть.

### Как работают совместные гаражи

1. У каждого пользователя при регистрации сразу создаётся свой гараж на сервере.
2. Кнопка «Пригласить» создаёт код (живёт 7 дней) — делится через системный Share.
3. Тот, кому дали код, жмёт «У меня есть код» → уходит заявка на вступление.
4. Любой текущий участник гаража открывает Гараж (или тянет вниз, чтобы обновить) и видит
   заявку — жмёт «Принять».
5. Вступивший, открыв Гараж в следующий раз, видит, что заявка одобрена: активный гараж
   переключается на общий, **локальная база WatermelonDB сбрасывается и синхронизируется
   заново** — осознанное решение: один и тот же локальный кэш не должен одновременно
   содержать данные двух разных гаражей вперемешку.

**Выход обратно в свой гараж**: кнопка «Покинуть общий гараж» в разделе «Участники» —
исключает вас из общего гаража на сервере, возвращает активный гараж на собственный, и
точно так же сбрасывает и пересинхронизирует локальную базу.

### Важно перед первым запуском синхронизации

Сервер (`mygarazh-server`) должен отвечать на `/v1/health` — см. раздел 3 выше. Больше
никакой отдельной настройки на стороне приложения синхронизация не требует: ни индексов,
ни правил доступа — всё это уже часть самого сервера.
