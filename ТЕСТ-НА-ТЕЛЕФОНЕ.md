# Тест на телефоне: инструкция для чайников

Цель: получить файл приложения, скачать его на телефон и установить. Собирается всё в облаке GitHub — ставить на компьютер ничего не нужно. Компьютер нужен один раз, только с браузером.

Понадобится: аккаунт GitHub (бесплатный, github.com), телефон на Android, и уже развёрнутый сервер `mygarazh-server` (если его ещё нет — см. `РАЗВЁРТЫВАНИЕ.md` в архиве сервера).

---

## Часть 1. Проверьте сервер (1 минута)

Приложение работает вместе с вашим сервером, а не само по себе. Откройте в браузере:

`https://api.mygarazh-app.ru/v1/health` (замените на свой домен, если он другой)

Должно показать `{"status":"ok"}`. Если нет — сначала разберитесь с сервером, собирать приложение пока рано.

Если домен сервера отличается от `api.mygarazh-app.ru`, откройте перед сборкой файл `src/config.ts` в архиве и поправьте строку `API_BASE_URL`.

---

## Часть 2. GitHub (5 минут)

Это **тот же самый репозиторий** `car-app`, что вы уже заводили раньше — новый создавать не
нужно. Каждая следующая сборка (новая версия приложения) — это просто обновление файлов в
нём же, а не отдельный репозиторий на каждый раз.

**Если репозитория `car-app` ещё нет** — создайте один раз: github.com → значок «+» вверху
справа → «New repository» → имя `car-app` → **Public** → «Create repository». (Public нужен,
чтобы скачать файл на телефоне без входа. Секретных ключей в коде нет вообще.)

**Если репозиторий уже есть** — просто откройте его.

**1. Загрузите файлы.** Внутри репозитория: «Add file» → «Upload files». Распакуйте архив,
откройте папку `car-app`, выделите **всё внутри** (Ctrl+A) и перетащите в окно браузера.
Дождитесь загрузки → внизу «Commit changes». GitHub сам заменит файлы с теми же именами на
новые и добавит новые — старые версии остаются в истории репозитория на случай отката.

Проверьте: в репозитории должна быть папка `.github` → `workflows` → `build-test-apk.yml`. Если её нет (на Mac скрытые папки не видны — нажмите Cmd+Shift+.), сделайте вручную: «Add file» → «Create new file» → в имени напишите `.github/workflows/build-test-apk.yml` → вставьте содержимое этого файла из архива → «Commit changes».

**Про нумерацию версий:** отдельно ничего указывать не нужно — каждый запуск сборки (часть 3
ниже) сам получает свой номер (`test-1`, `test-2`, ...), и ссылка на скачивание всегда ведёт
на самую последнюю. Старые версии остаются во вкладке «Releases» репозитория, если понадобится
вернуться к предыдущей.

---

## Часть 3. Сборка (15–25 минут ожидания)

**2.** Вкладка «Actions» → слева «Собрать тестовое приложение» → справа «Run workflow» → зелёная кнопка «Run workflow».

**3.** Ждите. Зелёная галочка = готово. Красный крестик = ошибка: откройте шаг с крестиком, скопируйте последние 30–40 строк (или сделайте скриншот) и пришлите — найдём причину.

**4.** Откройте завершённый запуск и прокрутите вниз до блока «Итог» — там ссылка на файл:
`https://github.com/ВАШ-ЛОГИН/car-app/releases/latest/download/car-app-test.apk`

---

## Часть 4. Установка на телефон

**5.** Откройте эту ссылку в Chrome на телефоне — скачается `car-app-test.apk`. Нажмите на скачанный файл.
- Если телефон пишет «Установка из этого источника запрещена» — нажмите «Настройки» и разрешите для Chrome.
- Если Google Play Protect предупреждает — нажмите «Всё равно установить».

**6.** Чтобы дать приложение другому человеку — отправьте ему ту же ссылку.

---

## Что работает в таком тесте, а что пока нет

Работает: регистрация по почте, **вход через Telegram-бота и через Яндекс ID**, согласие на обработку данных, гараж (включая приглашения и общий доступ), автомобили, записи о ТО, расходы, напоминания, синхронизация между несколькими телефонами, удаление аккаунта, замок по отпечатку.

Вход через Telegram заработает, только если на сервере настроен бот (см.
`РАЗВЁРТЫВАНИЕ.md` сервера, раздел «Вход через Telegram») и в `src/config.ts` вписано
правильное имя бота (`TELEGRAM_BOT_USERNAME`) — без этого кнопка просто вернёт ошибку.

Вход через Яндекс заработает, только если на сервере зарегистрировано OAuth-приложение
(см. `РАЗВЁРТЫВАНИЕ.md` сервера, раздел «Вход через Яндекс») — в само мобильное
приложение ничего дополнительно вписывать не нужно.

Пока не работает (появится отдельным этапом):
- вход через Google — убираем совсем;
- OBD2 (Bluetooth-адаптер) — понадобится реальное устройство для проверки.

Тексты политики конфиденциальности будут содержать пометки «[НЕ ЗАПОЛНЕНО: …]» — это нормально для теста, реквизиты заполняются в `legal/operator.json` перед публикацией.

## Как собрать заново после правок

Загрузите изменённые файлы в репозиторий (Add file → Upload files) и снова запустите шаг из части 3. Секретов в этой сборке нет вообще — вводить нечего.

**На будущее, чтобы совсем не перетаскивать файлы руками — GitHub Desktop.** Один раз
настраивается, дальше каждое обновление — пара кликов, и скрытые файлы (вроде `.github`)
больше никогда не потеряются, потому что перетаскивания через браузер просто не будет.

**Настройка (один раз):**

1. Скачайте и установите [GitHub Desktop](https://desktop.github.com).
2. Откройте его → «Sign in to GitHub.com» → войдите тем же аккаунтом, что и на сайте.
3. «File» → «Clone repository» → вкладка «GitHub.com» → найдите в списке `car-app` →
   внизу выберите папку на компьютере, куда положить (например, «Документы») → «Clone».
   Теперь у вас на компьютере — точная копия репозитория, живая связь с GitHub уже настроена.

**Дальше, при каждом обновлении (после того, как я пришлю новый архив):**

1. Распакуйте присланный архив.
2. Откройте папку, куда склонировали `car-app` в п.3 выше, и скопируйте туда содержимое
   архива поверх — соглашайтесь заменить файлы с одинаковыми именами (в Finder на Mac или
   Проводнике Windows это делается обычным копированием папки внутрь папки, «Заменить»).
3. Откройте GitHub Desktop — он сам заметит все изменения и покажет список файлов слева.
4. Внизу слева есть два маленьких поля для текста коммита — впишите в первое что-то
   вроде «Этап 3» (можно любые слова, это просто пометка для себя).
5. Нажмите синюю кнопку **«Commit to main»**.
6. Сверху нажмите **«Push origin»** — это и отправляет изменения на GitHub, аналог того
   самого «Commit changes» в браузере.

Готово — дальше как обычно: вкладка Actions на github.com → «Run workflow».
