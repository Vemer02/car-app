требования к подписи), сверено 07.10.2026. Правила меняются — перед отправкой перечитайте на странице
правил модерации раздел **12.2 «Чек-лист перед отправкой»**.

## За что RuStore отклоняет и как мы застрахованы

| Причина отказа (пункт правил) | Что у нас |
|---|---|
| Подпись **отладочным** сертификатом (2.14) | Закрывается **шагом 1**. Пока ключа нет, сборка подписана общим отладочным и печатает об этом предупреждение |
| Включён режим отладки `debuggable` (2.14) | В release-сборке выключен; «Паспорт сборки» проверяет это после каждой сборки |
| Название на телефоне ≠ названию в магазине (6.4) | Название задаёт сборка и оно же идёт в тексты (по умолчанию `CarApp`); в консоли впишите такое же |
| Иконка с прозрачными углами (6.6) | Готова `store/icon-512.png`: 512×512, сплошная заливка |
| Нет политики конфиденциальности в приложении и по ссылке (5.1) | Есть (редакция 3). Нужно выложить на сервер новые страницы |
| Нельзя удалить аккаунт в приложении (5.4) | Есть: «Гараж» → «Удалить аккаунт и все данные» |
| Вход только через сторонние мессенджеры (8.5) | Есть вход по почте и паролю |
| Не заявлен рекламный SDK (9.4) | **Шаг 4**: заявить Yandex Mobile Ads |
| Полноэкранная реклама без возможности закрыть (9.6) | У рекламного окна Яндекса есть кнопка закрытия — **проверьте на телефоне** |
| Скриншоты с системными элементами Android или чужой рекламой (6.6) | `store/скриншоты-и-модератор.md` |
| Функции в описании, которых нет (6.4) | Описание написано только по существующим функциям; **проверьте входы через Яндекс и Telegram** на телефоне и уберите из описания, что не работает |
| Модератору нечем войти | **Шаг 5**: тестовый аккаунт |

## Шаг 0. Решения до первой публикации

Эти вещи нельзя (или очень неудобно) менять после публикации.

**0.1. Имя пакета — решено: `ru.mygarazhapp.car`.** Это «паспортное» имя приложения; после первой публикации его
сменить нельзя (будет уже другое приложение). Оно стоит в сборке по умолчанию, настраивать в GitHub ничего не
нужно. Это же имя вписывается в проект push в RuStore Консоли и при добавлении приложения в Рекламную сеть
Яндекса. Старая тестовая сборка (`com.carapp`) на телефоне — **другое приложение**: новое встанет рядом,
старое удалите (перед этим убедитесь, что в «Гараж → Синхронизация» зелёная точка).

**0.2. Название — решено: `CarApp`.** Оно по умолчанию стоит в сборке (под иконкой на телефоне и в текстах
приложения), в политике и согласии (поле `appName` в `legal/operator.json`) и в письмах и сообщениях бота
сервера. В RuStore его нужно вписать **ровно так же**. Два риска (подробнее — `store/карточка.md`):

- название должно быть **уникальным** — найдите `CarApp` поиском в RuStore до отправки;
- правила (6.4) **рекомендуют русское наименование**, если это не зарегистрированный товарный знак. Это не
  запрет, но модератор вправе спросить. Запасные варианты: `CarApp: учёт и ТО` или русское название.

Если название придётся сменить, оно живёт в **трёх местах** (все три должны совпасть):

| Где | Как поменять |
|---|---|
| Под иконкой и в текстах приложения | GitHub → Settings → Secrets and variables → Actions → Variables → `APP_NAME` |
| Политика, согласие, страницы сайта | `appName` в `legal/operator.json` на github.com, затем пересобрать страницы |
| Письма и сообщения бота | `APP_NAME=...` в `.env` на сервере, затем `docker compose up -d` |

**0.3. Возрастное ограничение.** См. `store/карточка.md`.

## Шаг 1. Ключ подписи (самое важное)

Каждый APK в RuStore подписывается вашим сертификатом, и **одним и тем же на все версии**: иначе
пользователи не смогут обновиться. Хранить ключ нужно как пароль. Если потерять, заменить его можно только
через поддержку RuStore (support@rustore.ru), это долго. Ключ создаём **на вашем сервере**, а не у меня:
закрытый ключ не должен проходить через чат.

### 1.1 Создать ключ

Подключитесь к серверу по SSH и выполните:

```bash
apt-get update && apt-get install -y default-jre-headless
cd ~
keytool -genkeypair -v -keystore avtolyubitel-release.p12 -storetype PKCS12 \
  -alias avtolyubitel -keyalg RSA -keysize 2048 -validity 10000
```

Что спросит:
- **пароль хранилища** (придумайте длинный, запишите в менеджер паролей; вводимые символы не отображаются);
- имя, организацию, город, страну — можно ввести что угодно (например, ваше ФИО и `RU`);
- пароль ключа — если спросит, нажмите **Enter** (пароль ключа совпадает с паролем хранилища).

В итоге появится файл `avtolyubitel-release.p12`. Псевдоним (alias) — `avtolyubitel`.

### 1.2 Сохранить копии (до всего остального)

С вашего компьютера (PowerShell):

```powershell
scp root@5.35.86.121:~/avtolyubitel-release.p12 .
```

Положите файл минимум в **два разных места** (например, флешка и облако) и сохраните там же пароль.
Файл без пароля бесполезен, пароль без файла тоже.

### 1.3 Завести секреты в GitHub

Получите ключ одной строкой (на сервере):

```bash
base64 -w0 ~/avtolyubitel-release.p12; echo
```

Скопируйте **всю** длинную строку. GitHub → репозиторий `car-app` → **Settings** → **Secrets and variables** →
**Actions** → вкладка **Secrets** → **New repository secret**. Четыре секрета, имена в точности такие:

| Имя секрета | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | длинная строка из команды выше |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `avtolyubitel` |
| `ANDROID_KEY_PASSWORD` | **тот же** пароль, что у хранилища |

Нужны все четыре или ни одного. Сборка сама проверит ключ: откроет его и достанет закрытую часть. Если
строка обрезана, пароль или псевдоним неверны, она остановится сразу с понятным текстом (а не через
15 минут непонятной ошибкой).

### 1.4 Собрать и проверить

Запустите сборку (Actions → Run workflow). Должно быть:
- в шаге **2** строка «Подпись: настоящим ключом из секретов GitHub»;
- на странице запуска блок **«Паспорт сборки»** со строкой «✅ собственный ключ» и **SHA-256 отпечатком** —
  скопируйте его.

**Важно:** новая подпись не совпадает с отладочной, поэтому такая сборка **не установится поверх** старой
тестовой на телефоне. Сначала проверьте в «Гараж → Синхронизация», что точка зелёная (данные на сервере),
потом удалите старое приложение и поставьте новое.

### 1.5 Обновить push в RuStore Консоли

В проекте push замените отпечаток подписи на новый из паспорта сборки и убедитесь, что имя пакета равно
вашему `APPLICATION_ID`. Прежний отпечаток был от общего отладочного ключа.

### 1.6 Убрать ключ с сервера

Когда сборка с настоящим ключом прошла (значит, секреты рабочие) и две копии лежат в надёжных местах:

```bash
shred -u ~/avtolyubitel-release.p12
```

## Шаг 2. Регистрация разработчика в RuStore

Откройте [консоль](https://console.rustore.ru/sign-in) и пройдите регистрацию по
[инструкции](https://www.rustore.ru/help/developers/developer-account). Разработчиком может быть
физическое лицо, ИП или юрлицо. **Начните сейчас**: проверка занимает время, а для карточки она нужна
раньше всего. Добавить приложение может только роль «Владелец компании» — это вы.

## Шаг 3. Карточка приложения

Все тексты готовы в `store/карточка.md`: название, краткое (75 символов из 80) и подробное (2063 из 4000)

## Шаг 7. Отправка

1. Консоль → **Приложения** → **Добавить приложение** → название → **Загрузить версию**.
2. Загрузите APK: со страницы запуска сборки (шаг «Итог») скачайте `car-app-test.apk` — это тот же файл, который пойдёт в магазин (имя файла не важно). Обработанные файлы хранятся 14 дней: если за это время не отправили на модерацию, они удаляются.
3. Заполните карточку и декларации, нажмите **Отправить на модерацию**. Срок проверки — до 72 часов с момента отправки. Модерация вправе запросить дополнительные данные при первой публикации.
4. При отказе придёт письмо с причинами; исправьте и отправьте снова. Апелляция — support@rustore.ru (одна на решение).

**Обновления.** Код версии растёт сам с каждым запуском сборки (RuStore требует, чтобы он только
возрастал). Название версии для пользователей — поле `version` в `package.json` (сейчас `1.0.0`); меняйте
его при выходе новой версии. Подпись и имя пакета должны оставаться теми же.

## Известные риски (о них лучше знать заранее)

- **Ссылка `carapp://`** (открытие приложения по QR при передаче машины) — это «глубокая ссылка». Правила
  2.14 называют подозрительные глубокие ссылки признаком вредоносного кода. Наша открывает только экран
  «Принять передачу» и принимает один токен, но модератор может спросить, зачем она.
- **Разрешение `AD_ID`** добавляет рекламный SDK. В списках RuStore его нет, и консоль может пометить его
  как неизвестное. «Паспорт сборки» покажет полный список разрешений: сверьте с консолью.
- **Реклама при первом запуске.** Показывается и новому пользователю сразу после входа. Если модератор
  сочтёт это навязчивым (9.5), проще всего пропускать первый запуск.
- **Категория «Финансы»** формулировкой про «монетизацию просмотра рекламы» читается неоднозначно, поэтому в
  карточке выбрана «Транспорт и навигация» (в её описании прямо названы водители и страхование ОСАГО).
